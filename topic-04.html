Pratyek Sub-Topic — 5 Points

SQL vs NoSQL

PointMahiti
Kay aahe?SQL = table, join, ACID. NoSQL = flexible, scale-out.
Main GoalBarobar DB nivadne.
Ka use karaycha?Data cha prakar vegla asel tar DB vegla.
Kasa kaam karto?Users/orders = SQL. Feed/messages = NoSQL.
Kuthe use hoto?Users = PostgreSQL, Feed = Cassandra / DynamoDB.

Replication

PointMahiti
Kay aahe?Data chi copy anek servers var.
Main GoalRead scale + failover.
Ka use karaycha?Ek server gela tar data jau naye.
Kasa kaam karto?Primary var write, Replicas var read. Sync = slow pan safe, Async = fast pan thoda stale.
Kuthe use hoto?Pratyek motha DB.

Sharding

PointMahiti
Kay aahe?Motha table tukdyat vatne.
Main GoalWrite scale.
Ka use karaycha?Ek DB la sagla jamnar nahi.
Kasa kaam karto?Shard key: hash(user_id) % shards. Chukicha key = hot-spot.
Kuthe use hoto?WhatsApp messages, Instagram posts.

Indexing

PointMahiti
Kay aahe?Shodhnyasathi vegla rasta.
Main GoalRead fast.
Ka use karaycha?Table scan slow.
Kasa kaam karto?B-Tree / Hash index — read fast, write thoda slow + storage jast.
Kuthe use hoto?Search, email ne user shodhne, feed query.

Object Storage

PointMahiti
Kay aahe?File sathi — S3 / GCS.
Main GoalPhoto / video sathi swast + scale.
Ka use karaycha?Row query sathi nahi.
Kasa kaam karto?File upload → Object Storage, fakt URL DB madhe.
Kuthe use hoto?Instagram photo, YouTube video, Drive files.

Transactions & ACID

PointMahiti
Kay aahe?Ekdam sagla hoyil ki kahi nahi — ardha nahi.
Main GoalPaise / order madhe chuk nako.
Ka use karaycha?Atomicity, Consistency, Isolation, Durability.
Kasa kaam karto?Paise kapne + order banavne — ekach transaction.
Kuthe use hoto?Banking, payment, order.

Schema + Sharding Demo

users(id, name, email) • posts(id, user_id, image_url, created_at)

User nivad.
CREATE TABLE users (id BIGINT PRIMARY KEY, name TEXT, email TEXT UNIQUE);
CREATE TABLE posts (id BIGINT PRIMARY KEY, user_id BIGINT, image_url TEXT, created_at TIMESTAMP);
CREATE INDEX idx_posts_user ON posts(user_id);
